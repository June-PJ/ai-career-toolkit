# Delivery Checklist

Run this before creating the final DOCX.

## Content

- No placeholders such as `TODO`, `待补充`, `xx`, `N/A`, or fake metrics.
- Contact info is present and readable.
- Target role appears near the top.
- Work dates are concrete and consistent.
- Each project has a clear role boundary.
- Claims can survive interview follow-up.
- Similar bullets are not repeated across the same project.

## Technical Resume Fit

- Skills match the project evidence.
- "Familiar with" is reserved for tools the candidate can discuss confidently.
- "Understand" or "used in project" is used for shallow exposure.
- AI/Agent wording distinguishes model behavior from backend engineering work.
- Data, graph, and analytics projects do not overclaim ownership of downstream visualization or model reasoning.

## Submission

- Generate a clean DOCX as the skill output.
- Use a filename with name and target role.
- Avoid Markdown as the submitted file unless the employer explicitly asks for it.
